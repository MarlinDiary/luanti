# 真实课程服务器基础联调（2026-09-09）

## 结论与范围

SDK **0.10.4**、课程原生客户端 **0.7 / Luanti 5.17.0** 在用户给定的真实课程实例（端口 30000）上完成 **17 项基础联调**。服务器欢迎消息报告 **Luanti 5.16.1 / VoxeLibre**。本轮没有修改 SDK 或原生引擎代码，也没有安装服务器模组、改变服务器设置或重置远程世界。

这是该实例在本次配置下的基础兼容性证据，不是全部配方、地形或网络条件的远程验收。

## 真实环境中出现的情况

1. **出生点怪物攻击**：初始站立观察期间生命值从 20 降到 7，客户端聊天记录随后显示被骷髅击杀。一次复活后的移动实际走出了约 4 格，但受伤后按原有契约返回 `blocked / player_damaged`；这次没有列入成功项。课程初始化与示例 Agent 应检查生命、死亡和周围威胁，不能假设看画面等于暂停多人世界。结构化实体观察当前主要面向掉落物，不能把它当作完整怪物感知/战斗接口。
2. **测试参数导致的超时**：一次撤离试探指定了低一格的目标，却把 `max_drop` 设成 0，出现部分路径搜索和超时。后续基础导航使用默认允许下落一格的策略。这是测试约束问题，没有为此放宽 SDK 的受伤或未知地形保护。
3. **测试判定修正**：第一次视角测试把底层 `Submission.status == submitted` 错当成技能结果来比较，错误标成失败。保留原记录后改成核对实际 yaw/pitch，再执行完整 4 项导航/视角测试并通过。
4. **客户端生命周期**：原本以 `--go` 启动的本地测试进程在退回菜单时结束，当前普通客户端随后使用新进程。本轮不是全程零重启。真实服务器的全部测试使用同一个新进程；完成后正常退回主菜单，该进程仍在。
5. **静音与测量口径**：普通客户端设置已确认 `mute_sound = true`。`audio_enabled = true` 只代表声音管理器存在，不代表正在出声。观察模式下本地桥响应中位数约 97 ms；该测量包含客户端帧循环的等待，并不是网络 RTT。服务器欢迎消息里的 max lag 也不是 RTT。

## 重现与证据

完整证据在项目的 `build/evidence/course-server-v0.15/`：`verification.json` 保存实际命令、输出、退出码和哈希；三个阶段的 `*-results.json`、`*-samples.json`、`*-commands.json` 保存结果与轨迹。`remote-final-state.json` 保存清理和 Python 重连检查。

`read_only_probe.py` 只读取已经连接的客户端；`remote_skills.py` 执行有限的普通游戏操作，两者均没有登录密码、服务器管理命令或 fixture 导入。复现生产阶段会再次消耗正常材料，运行前应明确这一点。
