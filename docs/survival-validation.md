# 生存层验证记录

范围：SDK 0.11.0，课程客户端 0.8.0，固定 Luanti 5.17.0 / VoxeLibre 源码。
证据目录：`build/evidence/survival-v0.16/`。交付总记录为 `verification.json`；它要求每条正式验证命令退出 0、结果文件完成，而不只看部分场景状态。

## 基线与修正

- 原 SDK 0.10.4 的 242 项单元测试通过；新增生存 API/观察契约在原 SDK 上失败（`survival-red.json`），实现后相同契约通过。
- 普通任务继续在受伤时中断；战斗和撤离允许各自有界的损伤预算。取消、控制 epoch、死亡和时限仍优先。
- 真实引擎发现：VoxeLibre 怪物使用脚本生命值。`engine_immortal` 不是“不可以打”的标记。死亡动画的不可指向状态应停止攻击，自卫也应跳过这种目标。
- 中断发生在底层请求时，最初丢失了原因；现保留 `survival_interrupted`。生存反应已占用动作锁时，新提交的高层技能返回同样的重规划结果，不抛出普通“另一动作运行中”错误。
- 初始水下测试水池缺池底，角色掉出水域；补齐池底后使用同一个原生进程重测。SDK 没有添加传送或免疫伤害。
- 离开火源不会自动熄灭游戏的持续燃烧。最初它污染了后续两个独立回归的 HP 断言；现在火源测试等待正常燃烧效果结束再清场。未降低“无伤”断言。
- 第一次 wheel 构建使用了过旧的非隔离 setuptools；改用已有项目的隔离构建方式。Python 运行时依赖仍为零。

上述初次失败和中途被后续候选取代的运行均保留；正式结果不把这些运行计为通过。

攻击结果区分“提交”“不再观察到”“不再可指向”，不伪造服务器生命值或通用击杀确认。

## 测试运行方式

Python 迭代复用可见客户端。候选原生客户端完成一轮后，发行二进制启动一个新的持久测试会话；后续所有发行测试复用这一进程。两次启动都用独立 profile、静音和 macOS 焦点保护。没有反复重启学生正在使用的普通客户端。

审核记录检查声音后端关闭、观察中 `focused=False`，鼠标审计中无 CAPTURE/WARP。不会改用户系统音量。

## 真实课程服务器与平台边界

本轮为新增生存能力尝试打开独立的正常登录客户端，但 UI 控制工具连续超时；未输入凭据、未建立服务器会话，已结束该测试进程。见 `remote-validation.json`。
因此，**本轮新增生存能力未完成真实课程服验收**；之前的 17 项真实服基础联调仍归原来的报告，不挪用为本轮成果。

课程服务器、地图、规则和账户库存均未在本轮远程尝试中更改。测试实体与世界只存在于本地测试 profile。
Windows 原生构建/实机、多人竞争、丢包与长时断网、所有怪物/附魔/药水战术不在本轮通过声明内。

## 回滚

`build/evidence/survival-v0.16/rollback.py` 默认只校验；`--apply` 恢复本轮改动的源文件和此前的默认 macOS 客户端，并将被替换的新版本保留在工作区的回滚备份目录。

回滚脚本拒绝覆盖交付后又被修改的文件。正式验收在独立归档副本中实际执行回滚，并重新运行原来的 242 项单元测试；它不操作课程服、账户、地图、测试 world 或个人 profile，也不自动重启正在运行的客户端。
