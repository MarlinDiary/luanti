# 水边采集修复（SDK 0.11.8 / 客户端 0.8.0）

2026-09-10。仅修改 SDK 与测试，不修改游戏引擎、真实课程地图或课程规则。

## 问题与处理

- 同一水险场景中，0.11.7 只取得 2/3 个原木，剩余目标成为自身支撑；随后探索到超时。采集路径现在排除以目标为支撑的站位，批量采集站位也排除整组待挖资源。已站在原木上时，若周围有可达站位且下方支撑已知，则先走开再挖，不把该资源直接当成永久不可达。一般工作台/容器交互不使用挖掘限制。
- 已明确设置 `Traversal(allow_swim=True)` 时，浅水中已知可靠支撑、无伤害液体、头部空间清楚且完整碰撞体可通过的位置可作为涉水站位。默认仍不进水；未知地面、头部淹水、熔岩、低顶棚不被当成涉水位置。
- 上一轮未发布浅水候选曾在选站位时重复完整算路约 4 秒，角色在此期间下沉；路径又跳过了仅为拓扑投影的初始水面节点，横向撞入岸壁。现在先按覆盖率与距离筛选少量候选，只验证到首个可达站位；若实际仍在水面下，则先在当前水柱恢复高度，再沿岸边路径移动。没有修改速度、碰撞、重力或反作弊规则。
- 恢复水面高度时仍保留原目的地的横向坐标，包括起点和终点在同一水格的情况；不把“已经浮起来”误当成“已到达目标”。
- 掉落物仍以实际背包增量确认，水流带走的物品按观察位置追踪；不把“节点被挖掉”或“实体消失”当作已拿到材料。
