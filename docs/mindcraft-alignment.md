# Mindcraft 行为源码对照与本轮实现

版本：SDK **0.11.4**；原生客户端仍为 **0.8.0**。本轮不修改课程设计、远程地图或服务器设置，不引入 Node/Mineflayer 安装依赖。

## 方法与来源

从触发条件、动作执行、途中观察、结束条件、中断清理逐项比较，而不是看到同名 API 就标记能力等价。阅读固定版本原始代码；只下载源码，不执行参考仓库里的启动/安装/游戏指令。

主参考：Mindcraft commit `5f3acc87b479864124173de444f31fa5538f94a6`：

- [modes.js](https://github.com/mindcraft-bots/mindcraft/blob/5f3acc87b479864124173de444f31fa5538f94a6/src/agent/modes.js)：优先级、触发、互斥与回到规划者。
- [skills.js](https://github.com/mindcraft-bots/mindcraft/blob/5f3acc87b479864124173de444f31fa5538f94a6/src/agent/library/skills.js)：完整游戏动作和停止条件。
- [agent.js](https://github.com/mindcraft-bots/mindcraft/blob/5f3acc87b479864124173de444f31fa5538f94a6/src/agent/agent.js)：进食参数、生命周期、规划者交接。
- [world.js](https://github.com/mindcraft-bots/mindcraft/blob/5f3acc87b479864124173de444f31fa5538f94a6/src/agent/library/world.js)：附近对象与资源查询。

同时读取官方 npm 发布包 `mineflayer-pathfinder@2.4.5`、`mineflayer-pvp@1.3.2`、`mineflayer-auto-eat@3.3.6`。这是 Mindcraft 声明依赖范围中的精确版本样本，不是它某次安装的 lockfile 重建，也不是本轮运行了 Minecraft 做性能对比。

源码、原许可证、下载地址和 SHA-256 留在 `build/evidence/mindcraft-alignment-v0.21/reference/`；`sources.json` 保留了最初三个错误拆分文件路径的 404，实际实现定位到集中式 `skills.js`。`dependency-sources.json` 保存插件包及逐文件哈希。Mindcraft 为 MIT，Copyright (c) 2024 Kolby Nottingham；本轮 Python 实现是基于行为对照的适配，不直接打包其 JS 源码。

## 本轮三个最小修改

1. **反应执行中的优先级检查**：旧实现只有执行前决策，进入一次长反应后不再检查高优先级。现在 `Context.read` 用已经取得的快照通知 supervisor；旧动作正常退出后再执行新反应。无第二个 socket、无并发输入。受伤记录在抢占前保留。
2. **自卫持续重选目标**：旧实现 `defend` 只调用一次对初始目标的 attack。现在自卫模式持续重选范围内目标，并在瞄准后再次检查；目标切换不重置武器冷却和总攻击预算。显式 `attack_entity` 不受影响。
3. **撤离结束复查**：距离合格后连续观察 `settle_time`，重新接近就继续走。移动目标留下按已观察追速计算的余量；路径终点再超过接受边界，避免追兵移动及临近终点减速导致永远达不到边界。这是 Luanti 跟随器适配，不是宣称参考代码已有相同确认窗口。

可配置行为仍留在一个完整动作中，没有把“逃跑”拆成学生需要手动拼的几块。

## 验证与交付

最终命令、输入、字面输出、退出码、源码哈希和产物哈希见 `build/evidence/mindcraft-alignment-v0.21/verification.json`。本轮先保留 0.11.3 源码和哈希，在副本修改，最后通过补丁应用/回退验证后发布。

- 初次测试副本漏带 engine 元数据，导致两个测试环境错误；补齐后 **325 项旧单元测试通过**，该错误记录未删除。
- 新的首批 9 项行为契约在旧实现中 **6 项失败**；修复后同输入通过。后续增补死亡/控制优先、重复抢占、损伤记录、显式目标绑定和观察截断等边界。
- 初次本地原生对齐：多敌人自卫、战斗中低血抢占成功；移动追兵撤离超时（30 秒）。失败位置/命令/观察全部保存。区分路径终点和接受阈值后，同一追兵场景 **7.574 秒成功，连续合格观察 1.104 秒**。
- 最终发行 wheel 的完整单元/本地原生回归结果在本节末尾列出；只有程序退出且 `results.json` 核实后记为通过。
- 所有原生验证复用既有隔离客户端进程，声音关闭，不重启 GUI、不操作真实课程服。隔离场景由 fixture 创建；这里的给装备/重置地图仅用于本地测试，不证明真实课程服从零生存成功。
