# 复杂场景与持续运行验证（SDK 0.10.4）

本轮在现有静音、可见的 macOS 客户端及固定版本 VoxeLibre 本地测试世界完成。测试不重启原生客户端，不抢鼠标。结论只覆盖这些输入和运行时长，不代表任意地图、服务器、网络或平台均已验证。

## 结果

- 10/10 个复杂场景，74/74 个简单行为回归，242 个单元测试通过。
- 持续运行完成 18 圈、623.9 秒主动操作、实测约 2097.9 格路程，串联 55 个技能调用；同一世界内不重置库存或地形，每3圈只重连 Python。
- 每步检查真实库存、HP、输入释放、菜单关闭、结束后的视角和位置漂移；普通放置和桥段分别检查眼高，避免再次遗漏“脚没动但相机蹲起”的问题。

## 长流程发现并修正的问题

两格高隧道中，脚边矿石的中心可能被上方石块遮挡，但侧面仍然露着。旧实现只检查中心射线，误判矿石不可达，甚至回到地面继续搜索。

修正仍优先使用原来的中心瞄准；中心被遮挡时，只在已观察到的完整方块表面寻找有限的可见落点。选工具之后保留已经确认的瞄准方向，不再重新瞄准被挡住的中心。没有扩大触及距离，也没有增加自动挖遮挡物、寻找钻石或选择采矿策略的功能。

相同真实场景、相同技能输入：0.10.3 采集0个并返回 `resource_not_found`；0.10.4 采集3个生铁。新增单元测试覆盖侧面、相邻矿挖掉后露出的下侧边缘、隐藏矿、未知空间、半砖、距离上限、原有中心瞄准和选工具后的瞄准保持。

## 重跑

```sh
python3 tests/integration/complex_audit.py --sdk sdk/src --session /ABS/PERSISTENT_SESSION --out /ABS/NEW_EVIDENCE --only ore_sidewall,mixed,production,recovery,mining_resume,dynamic,seeds,soak --soak-seconds 600
```

检查器只连接已经启动的本地隔离测试会话。重置夹具仅用于测试世界，不用于课程公共服务器。人工接管后停止，不自行重新获取控制。结果目录记录冻结场景、逐步参数及 SkillResult、客户端帧、服务器物理轨迹、检查点和内存测量。进程正常结束并且完整结果文件通过，才算整套完成。

## 边界与保留的失败记录

- 生产流程的初始夹具提供工作台、熔炉、箱子和煤；脚本明确选择每个目标。这不是从空手到钻石的自动开荒证明，学生仍需设计目标、路线、资源和恢复策略。
- 第一版动态墙在1.8秒生成时与角色重叠，SDK 受到伤害后返回 `player_damaged` 并停止。另用0.65秒提前生成墙验证无重叠的动态绕行；原始受伤轨迹仍保留，不算成功绕行。
- 第一版桥段指标把预算耗尽后的取物、返回和第二段施工算成一个桥段；按新施工起点重新划分，未放宽2度朝向和0.04格眼高门槛。
- 检查器初版的第二连接、超出6的观察半径属于测试器错误；失败命令被保存，未计为 SDK 通过。
- 10分钟是有限持续运行检查，不是无限时长无泄漏证明。Python 内存包含测试器主动保留的完整遥测，不能直接当作 SDK 泄漏指标。
- 本轮没有覆盖 Windows 实机、真实远端网络抖动/断线、不同服务器自定义内容或任意时长运行。

完整证据位于 `build/evidence/complex-v0.14/`：`VERIFICATION.md`、`verification.json`、`REVIEW.html`、`scenario-contracts.md`。补丁与回滚均在独立文件副本上实际执行验证；原始 SDK 文件及旧安装包保留。
