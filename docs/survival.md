# 生存技能与快速反应层（SDK 0.12 / 客户端 0.9）

当前 SDK **0.12.0** / 客户端 **0.9.0**；本页后半部保留逐版本沿革，最新完成项与待验项见 [课程版收尾](course-completion.md)。进入生存作用域时，已知危险立即建立待处理反应；普通技能的新观察发现缺氧、接触危险、持续燃烧、投射物或爆炸威胁时也先交接，再由唯一工作线程复核执行。

目标是与 Mindcraft 的分层对齐，不是把 Minecraft 的服务器机制照搬到 Luanti。

| 层次 | 本项目提供 | 学生决定 |
|---|---|---|
| 观察 | 附近已复制的生物名称、位置、速度、实例标识；HP、呼吸、饥饿和可见 HUD 图像；背包武器数据 | 如何利用信息、识别未适配生物 |
| 完整动作 | 近战/远程、盾牌、投射物侧移、爆炸撤离、进食/装备、浮出水面、离开接触危险、到已观察水域灭火 | 使用哪个动作、何时切换任务 |
| 快速反应 | 可开启/暂停/配置的自动进食、自保、避敌或自卫；与普通任务互斥 | 风险偏好、禁用或替换策略 |
| 规划 | 返回 `SkillResult` 和生存事件，保留原有采集/合成检查点 | 找矿、造桥、下矿/返程、升级装备、资源获取与 LLM 决策 |

## 最小使用方式

先打开更新后的课程客户端、正常登录服务器，再运行：

```python
from luanti_course import Game, SurvivalConfig

with Game.connect() as game:                 # 这里只观察，不接管
    with game.control():                    # 明确交给脚本；Esc 仍优先
        with game.survival() as survival:    # 显式开启；默认避敌、自动吃已有食物
            result = game.collect("mcl_core:tree", 1)
            print(result.to_dict())
            if result.reason == "survival_interrupted":
                survival.wait_idle(timeout=30)
                print(survival.events())
                state = game.observe()
                # 根据新状态重新计划；这里不自动重放刚才的 collect。
```

偏好战斗可用 `game.survival(SurvivalConfig(enemies="defend"))`；
`enemies="off"` 关闭一般避敌/自卫，`self_preservation=False` 关闭紧急自保。
`auto_eat=False` 关闭自动进食。三者独立，配置可替换，不嵌入采矿策略。
默认饥饿阈值 14/20，受伤且饥饿低于 18 时也尝试进食；只使用背包已有食物。
默认 12 格内避敌，撤离到 14 格，用不同进入/退出阈值避免来回切换。
默认反应检查周期 150 ms，不需要等 LLM 返回；网络和原生响应延迟会影响实际反应时间。

## 单独调用

- `game.observe().entities` → `Entity` 元组。`name` 是协议复制的名称；`hp` 不作为可信生物生命值暴露。
- `game.observe().hunger` → 0–20 或 `None`。只识别固定版本 VoxeLibre 的饥饿 HUD，不猜隐藏饱和度。
- `game.attack_entity(entity, timeout=45)` → 选择已有装备、接近、平滑瞄准、按武器冷却攻击。
- `game.attack_entity(entity, one_hit=True)` → 请求一次普通攻击；结果不声称服务器一定造成伤害。
- `game.attack_ranged(entity, shots=1)` → 使用已有弓箭；以弹药实际减少确认射击。
- `game.block_with_shield(entity, duration=1.2)` → 对着可见威胁举盾；以可见 HUD 确认举起和释放。
- `game.avoid_projectile(entity)` → 有盾则举盾，否则按已观察速度平滑横移一次。
- `game.survive_blast(entity)` → 对可见爆炸类实体举盾，或连续撤离到安全距离。
- `game.flee_from(entity, safe_distance=12)` → 追踪指定威胁，同时避让其他已观察的敌对生物；省略实体时避开当前识别的敌对生物。
- `game.defend_self(min_hp=6, damage_budget=10)` → 自卫；低于血线或累计损伤预算后转为撤离。
- `game.eat_best_food()` → 选择并吃一个已有的合适食物。库存减少确认消耗，另记饥饿前后值。
- `game.equip_best_gear()` → 装备更高防护点数的已有护甲、按实时物品能力挑武器，不自动制造装备。
- `game.recover_air()` → 利用已观察到的水域路线浮到空气处。
- `game.escape_hazard()` → 离开脚下/身体接触的伤害方块；不自动放水、不修改地形。
- `game.extinguish_fire()` → 前往已观察水域并确认火焰 HUD 消失；无水或水点失效时返回 blocked。

实例标识与 **当前 Game 连接** 绑定。重连后重新观察；不接受一个裸数字 ID 来攻击。
原生端在每帧正常射线检测之后核对目标实例。目标变化时清掉攻击按键，不把攻击变成挖地或 PvP。
所有攻击继续经过原游戏的距离、遮挡、物品冷却、服务器伤害逻辑。

VoxeLibre 的怪物采用脚本生命值，原生 `engine_immortal=True` 只是关闭引擎自带扣血，不表示脚本怪物无敌。
目标消失/进入不可指向的死亡动画后停止攻击；结果明确写 `target_no_longer_observed` 或 `target_no_longer_attackable`，`killed=None`，不把消失、离开观察范围、死亡混为一谈。

## 中断与互斥

同一 `Game` 只有一个动作所有者和一条连接。反应层先发出中断请求，等原任务清理按键/表单并释放动作锁，再执行反应。
普通技能返回 `cancelled / survival_interrupted`；反应执行中提交新技能也返回这个结果并标明 `started=False`，事件包含反应的结果和 `replan_required=True`。
不自动重放会消耗材料、挖矿或放块的任务。学生可重新观察，显式使用已有检查点续做。
普通任务保留“受伤中断”；战斗/撤离使用各自有限的损伤预算，死亡、失去控制、Esc 和超时仍停止。

`survival.pause()` 暂停快速反应；`game.stop()` 同时暂停它，避免刚停止就又动起来。
`survival.resume()` 需控制权仍有效。F8/人工切换、死亡或断线会暂停，不偷偷重新获取控制。
自定义低层循环不响应中断、两秒内不释放动作锁时，反应层停掉输入并暂停，而不是抢着写控制。
事件队列保存最近 256 条，序号可检测遗漏；脚本应定期调用 `events()` 取走。

## 与参考实现的关系和边界

参考固定版本 Mindcraft [`modes.js`](https://github.com/mindcraft-bots/mindcraft/blob/5f3acc87b479864124173de444f31fa5538f94a6/src/agent/modes.js)、
[`skills.js`](https://github.com/mindcraft-bots/mindcraft/blob/5f3acc87b479864124173de444f31fa5538f94a6/src/agent/library/skills.js)、
[`agent.js`](https://github.com/mindcraft-bots/mindcraft/blob/5f3acc87b479864124173de444f31fa5538f94a6/src/agent/agent.js) 的完整动作、模式开关、抢占/快速生存反应和自动进食分层。
这里不是 Mineflayer 协议移植，也不是 Mindcraft 全部能力等价的声明。

- 附近对象限客户端已复制的 16 格范围、128 个；不是全图搜索或视线可见性保证。超限/受服务器限制时动作明确报告。
- 敌对类型使用 VoxeLibre 名称白名单；未知模组、中立生物保持未分类，某些随昼夜/状态转变的生物仍采用保守避让。学生可自己选择明确实体执行动作。
- 不读取服务器隐藏生命值、仇恨目标、隐藏饱和度；HUD 改版、隐藏或不唯一时饥饿为未知。
- 自动选食物排除腐肉、蜘蛛眼等已知不适合项；额外模组/课程特殊食物应更新禁食配置和适配器。没有食物时不会自动种田找食物。
- 武器按 `fleshy` 伤害选择，护甲按目录防护点数；弓和盾按物品分组适配，不是所有附魔、状态效果、远程武器或怪物弱点的完整战术系统。
- 脱离接触伤害不等于解除持续燃烧/中毒；持续燃烧会另行寻找已观察水域。被围困、没有水或没有已观察通路时返回失败，不保证生还。
- 不创造“口渴”机制：固定游戏的普通水瓶没有补充口渴值的效果。药水/食物效果依原游戏规则。
- 高层寻路默认不额外挖路、建桥或授予物品。学生仍设计长程发展策略。
- Mac/Windows 共用纯 Python API；Windows 构建/ZIP 流程已有自动化，原生 runner/实机启动仍需单列证据。

验证范围和失败修正见 `docs/survival-validation.md`。原来的真实课程服 17 项基础联调不算作这些新增生存能力的远程验收。

## 0.12：可见生存信号与自然抢占

- 客户端 schema 7 导出最多 128 个玩家本来可见的 HUD 图像纹理名，用它确认持续燃烧和盾牌状态；不导出服务器 Lua 内部计时器。
- 投射物只在实测轨迹于 1.25 秒内接近玩家身体时触发；静止、远离和未知实体不猜成箭。
- VoxeLibre 当前的 `mobs_mc:stalker`/`stalker_overloaded` 作为可见爆炸威胁；没有隐藏引信预测。
- 正在连续撤离时不为每一支短命箭取消/重启；撤离本身保持规避运动。进食、静止攻击等动作仍可被来袭箭抢占。
- 模型无关参考 Agent 使用同一 `SkillResult` 与生存事件；它不扩大观察权限，也不自动恢复被中断的课程任务。

## 0.11.1 真实服修正

真实课程服首次回归发现：干燥陆地上的 `recover_air()` 错误寻找水面，返回 `air_route_unavailable`。
现在先检查已观察到的身体空间是否干燥且无碰撞；已恢复呼吸则原地成功，低呼吸时有界等待确认；水下满呼吸仍执行脱水路线，未知空间不当作空气。
本轮真实服 5 项基础检查和 SDK 297 项单元测试通过；实战、实际进食、水险/火险触发未在本轮真实服出现，不算已验证。见 [真实服生存回归](remote-survival-validation.md)。

## 0.11.2：动态生存与长流程回归

- 追击分段接近客户端已复制、但局部节点观察尚未覆盖的生物；最终攻击仍要求正常距离和原生射线命中。
- 目标移动导致一次攻击被原生端以 `entity_not_in_crosshair` 拒绝时，重新观察/瞄准；不计作已提交攻击，也不重试控制权或实体身份错误。
- 撤离优先走完整安全距离；观察范围内只能小幅改善时继续经过已知可通行地形，不将未知空间当作空气。撤离终点留 0.5 格余量避免路径容差造成反复重算。
- 紧急撤离/脱险失败后短周期重新评估，不固定停等 3 秒；仍返回 `replan_required`，不保证在多敌围堵中生还。

参考学生循环见 `examples/survival_collect.py`：保留已观察的局部地图、消耗生存事件、按新背包计算剩余数量、有界重新计划；不自动复活，失败反应交给规划者处理。

本轮 17 项本地生存、两条本地长流程通过；真实课程服夜间围堵验收失败，真实进食与环境危险验收仍缺证据。详见 [本轮完整记录](survival-live-validation.md)。

## 0.11.3：短距离撤离与绕敌约束

- 一格退路也实际执行，不套用普通远程寻路的“两格内提前结束”。部分路线走完后仍检查真实距离；走到死胡同明确返回失败，不把一点进展写成脱险成功。
- 陆地/水面路径拉直、提前跳过拐点和最终移动段都保留撤离的近战距离约束。几何通畅不等于沿途没有敌人。
- 指定一个追兵时，其他已观察敌人仍参与避让。出现新敌人或敌人明显位移时停止旧移动段并重新规划。
- 这是局部、静态距离约束加短周期重规划，不是动态碰撞预测或保证免伤；远程攻击、爆炸范围、完全围堵仍可能导致失败。
- 新增内部远程验收工具：预先给定完整步骤；观察停滞、低血、死亡、人工接管或总超时会关闭本次工具自己启动的客户端。它不自动复活、不等人工追加命令，也不接管其他客户端。仅停止 Python 输入不会让联网角色离开危险。

回归与当前边界见 [撤离修复验证](retreat-validation.md)。真实服验收和旧装备恢复仍单独跟踪，不由本地测试代替。


## 0.11.4：从参考源码对齐行为，而不只对齐名称

- `defend_self()` 在动作内持续观察并选择范围内最近的可攻击敌人，不再只处理进入动作时的第一个目标。切换目标共用攻击冷却、累计攻击次数与伤害预算；执行途中无可攻击敌人连续 0.6 秒后返回 `no_attackable_threat`（进入动作时本来没有威胁则直接返回）。`attack_entity(target)` 仍绑定用户指定的那个实体。
- 正在执行的生存反应也会在 SDK 技能读取新观察时检查优先级：呼吸恢复 → 接触危险撤离 → 避敌 → 自卫 → 进食。高优先级先让旧动作清理按键、释放锁，再重新观察和执行；记录 `reaction_preempted`。同级不互相重启，低优先级不抢高优先级。网络阻塞或不调用 SDK 观察的自定义循环不承诺即时抢占。
- `flee_from(..., settle_time=1.0)` 在最近威胁持续位于指定距离外，或持续没有观察到威胁，达到确认时长后才返回。确认中重新靠近就继续撤离；时长允许 `(0, 5]` 秒。`defend_self` 的低血撤离和 `SurvivalConfig(settle_time=...)` 使用同一参数。
- 对正在追来的实体，使用其已复制速度给移动目标留出确认余量，并把寻路目标与结束阈值分开，避免减速停在移动阈值边缘。确认期间仍保持原有超时、死亡、人工接管和观察完整性检查。
- `distance_reached`、`no_threat_observed` 仍只表示限定范围和时间内的观察结论，不表示敌人失去仇恨、远程攻击够不着，或角色接下来一定安全。更长程离开危险区和何时恢复采集由规划者决定。

## 0.11.5：反应交接与进食后的持物恢复

- 配套 `survival_collect.py` 只把带 `details.intervention` 的 `cancelled / survival_interrupted` 视为正常优先级交接；后继反应失败、普通取消、失去控制和暂停仍停止。重新采集前再读一次背包，而不是使用等待前的旧数量。
- `Survival.wait_idle()` 在被抢占的旧反应结束、后继反应尚未开始的交接期间继续等待；下一次观察确认反应已不需要时才清除 pending。暂停、退出或控制丢失仍清理 pending，不增加控制线程或连接。
- `eat_best_food()` 和自动进食正常成功后，尝试恢复原先的持物。按名称、磨损与含元数据的 `stack_key` 匹配，不仅看物品槽；快捷栏满导致工具移入背包时也查找原物品。原空手槽仍为空时恢复空手。
- 恢复前仍读取新观察并检查取消、控制权与紧急优先级；中断路径不执行“恢复持物”的 finally。持物被其他操作改变、原物品已消失或缺少身份信息时不覆盖它。食物已消耗但后续恢复失败时，保留消耗和失败记录，不自动再吃。
- 直接 `game.eat(item)` 的持物语义不变。本次没有增加自动找食物、找矿、重试死亡或长程任务规划。

同输入红绿测试、发布包原生回归、真实服低血退出证据和未覆盖项见 [SDK 收尾验证](sdk-finishing.md)。
