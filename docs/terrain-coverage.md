# 地形覆盖与验收边界（客户端 0.7 / SDK 0.10）

目标是自然移动、按观察规划，并为有实际通行方法的地形组合提供合适策略。“明确受阻”不算成功通过。没有有限的测试能证明所有地图、模组、物理和网络组合全覆盖。

## 实现与实体测试矩阵

| 类别 | 策略 / 用例 |
| --- | --- |
| 平地、墙角、动态新增墙 | 连续前视跟随、有界 A*、观察后重规划 |
| 整块台阶、半砖、雪、地毯、四向楼梯 | 实际碰撞盒和分数高度，不把节点都看作整块 |
| 窄桥、低顶通道、门边窄净空 | 连续支撑、角色真实宽高、非对称净空偏移 |
| 梯子 | 普通上/下攀爬 |
| 木门、栅栏门 | 右键、世界确认后再规划；铁门拒绝交互后绕行 |
| 一格/两格沟壑、边缘静止起步 | 普通跳跃，物理可行性检查与必要的助跑 |
| 两格落差 | 显式 max_drop=2，正常下落与落地 |
| 三格宽断路、两格高台 | 消耗真实方块搭桥或垫台阶 |
| 整块障碍 | 显式挖掘，普通工具选择、逐块服务器确认 |
| 冰、黏液、蜂蜜、灵魂沙 | 原生地面物理，连续速度/位置反馈；冰面转弯单测 |
| 浅水、深水水面、转向、出入水、流动水夹具 | 独立水中控制，上岸不延续成地面跳跃 |

## 自然度判定

不以“起伏越小越好”衡量游泳。保留原生浮力/重力、入水和正常水面起伏；重点检查出水后的多余弹跳、反向摆动、碰岸停滞、转向突变。旧版同输入的上岸额外跃升约 0.85 格，0.7 把游泳输入反馈移到物理子步，检查对应夹具没有额外地面跳跃；详见 [连续动作](fluency.md)。门、施工、落地换向和换气允许有目的停顿；普通平地前进不应每格停一下。

服务器网络采样的瞬时 yaw 峰值不等于渲染相机转速；相机逐帧插值另外用实际 C++ 方法验证。物理轨迹指标是操作性验收，不能代替用户对画面观感的最终判断。

## 尚未建立的保证

- 任意自定义模组、角色尺寸、载具/移动平台、瀑布/强水流、传送门、复杂跑酷和超出观测范围的长期生存规划。
- SDK 0.7 增加自动架梯/补背墙、阶梯式下挖、隧道净空和有支撑的图纸施工，详见技能工作流。任意盲井、完全无支撑的悬空放置仍不视为可行路线。
- 没有可通行路线、材料不足、受保护区域或物理不可达目标不保证成功；动作预算和明确的受阻结果仍有效。
- 官方真实生成世界的广泛随机测试、网络高延迟/丢包、Windows 原生实机以及实际课程服务器，仍需各自验收。

测试全程静音，不改变系统音量，不抓取或移动桌面鼠标；[持久会话](testing.md) 避免反复开关窗口。
