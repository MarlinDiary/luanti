# SDK 0.11.3：继续修复撤离与验收编排

## 改了什么

1. `combat.flee`：短段跟随改用实际到达容差，不再用两格内提前退出的 `partial` 行为；保留当前位置到网格中心尚未完成的短距离进展。
2. `skills.follow_path`：路径拉直、拐点跳过及实际移动段都检查调用方的临时约束。撤离传入“整段到已观察威胁的最近距离”约束，而非仅检查格点和地形。
3. 指定追兵不再屏蔽其他敌人；出现新敌人或敌人相对规划时明显位移后撤销旧移动段，重新规划。仍只有已复制信息，没有隐藏地图、生命值或仇恨数据。
4. 内部 `remote_survival_audit.py` 先读取完整有界计划，没有交互式命令等待。独立看门狗在总期限、连接期限、观察停滞、血线、死亡或人工接管时结束自己启动的原生子进程；SDK 卡住也不会无限等待。仅连接该子进程 PID 的控制端点，禁止聊天命令和自动复活。

原生客户端保持 **0.8.0**，SDK 为 **0.11.3**。

## 可复现结果

证据目录：`build/evidence/retreat-v0.19/`。

- 一格短通道：修改前 `short-tight-red-live/results.json`，6.006 秒重规划 112 次，坐标没有变化，超时失败。第一次较宽的两格通道没有复现，保留在 `short-red-live/`，不计失败。
- 同一格短通道：修复后 `short-final-green-live/results.json`，0.602 秒、1 次规划，实际退后约 0.85 格，达到设置的 3.8 格安全距离。
- 第一版修复到 3.787 格仍差一点达标，保留失败 `short-tight-green-live/`；随后修正当前位置网格中心和最终容差，未降低成功距离标准。
- 绕敌：第一版临时约束仍在拐点提前跳过后失败，见 `multi-live/`。修复后 `detour-corrected/` 实际完成绕行，采样最小距离 1.843 格（约束 1.8 格）。这是运动采样，不是连续帧或零风险证明；旧失败的最小距离混入场景准备采样，不用于性能对比。
- `final-unit.json`：322 项测试通过，包括 8 项撤离跟随回归、9 项验收生命周期测试。生命周期测试确实启动并结束隔离的本地子进程，未用真实课程角色测试“死亡退出”。
- 安装 wheel 后的实际本地引擎回归：`wheel-survival/` 17/17 场景通过；`wheel-multi/` 4/4 撤离检查通过；`wheel-long/` 两条长流程共 8/8 动作检查通过。完整命令、输出和退出状态在 `verification.json`。双敌样本约 5.1 秒达到最近 13.01 格距离，结束 HP 18/20；曾受伤，不是无损逃生。
- `wheel-multi` 的死胡同场景应返回失败：先实际退到可达位置，再报告无路；不将部分进展当成成功。
- 动态怪物运动存在随机性，双敌成功样本不等于所有多敌布局均能逃生。单位测试另外覆盖陆地/水面平滑约束、其他敌人、新威胁重规划和无效移动段停止。

## 真实服与学生接口边界

本轮没有再启动真实课程服，没有新增远程游戏操作、自动复活或地图/配置修改。此前真实服死亡、掉落装备未取回、实战与完整长流程验收未完成的状态不由本轮本地结果覆盖。

- 真实服装备回收、成功实战、实际进食、水险/火险及完整长流程仍待后续有界验收。
- 新远程测试器拒绝已死亡/菜单占用的初始状态。复活过渡菜单问题尚未修复，也没有绕过控制权限制。
- 看门狗是测试编排保护，不是学生 SDK 自动断线/复活策略；网络退出也不承诺角色免伤。
- 撤离使用短周期局部规划和保守距离约束；没有新增远程攻击闪避、爆炸预测或全局生存规划。
- Mac 本地完成回归，Windows 实机仍待验收。学生长程资源策略保持显式。
