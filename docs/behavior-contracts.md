# 简单场景动作检查

先写预期、冻结场景，再运行基线与候选。`success` 只是功能条件之一。

## 记录什么

- 客户端实际 yaw/pitch、位置、眼位、速度：约 30 ms 轮询，去除重复原生帧，记录 P95 和最大采样空隙。
- 实际请求、规划路径、技能事件：区分转向、移动、工作、确认和停止。
- 服务器日志：交叉检查物理、跳跃、潜行按键、世界变化。服务器 yaw 更新不等于逐帧相机轨迹。

## 简单场景预期

| 类别 | 应有动作 | 判错示例 | 合理例外 |
| --- | --- | --- | --- |
| 直走、各斜率和朝向、短停 | 转向后沿目标线走，减速停稳 | 追格点左右摇、无故停、越点回头 | 未知区域只推进到已观测范围 |
| 单障碍、门/栅栏 | 连续绕行，必要时开门 | 反复撞同一点、开关门 | 必要绕障和交互确认 |
| 台阶、楼梯、薄地形、落差和沟 | 使用真实碰撞盒，必要跳跃，过点不回头 | 某朝向错误绕远、连跳、落地转圈 | 助跑、落体、梯子接入与攀爬分阶段 |
| 水面、潜水、上下岸 | 稳定目标方向，高度反馈不过度纠正 | 快速出入水、绕点旋转、岸上多跳 | 入水落体、自然起伏、已有下沉的恢复 |
| 冰和慢速地面 | 尊重原生摩擦、加速，提前刹停 | 仍滑动便成功、越点回走 | 较长减速距离 |
| 搭桥 | 看着施工面倒退铺设 | 每块转身、施工阶段摇头 | 入口和出口转身按实际事件划分 |
| 挖掘、采集 | 瞄准后稳定挖掘，批量后捡取 | 挖时乱动、无目标换位 | 真实掉落物随机散落、材料确认 |
| 施工、造梯 | 复用有效站位，普通放置站立不蹲 | 每块蹲起、重新优化站位、重复放置 | 交互面需要潜行；造梯完成后下降是单独阶段 |
| 背包、装备、合成、箱子、熔炼 | 无关身体动作保持静止 | 乱转和走动、重复靠近同站位 | 合成依赖、工作台放置、服务器和炉子等待 |
| 进食 | 保持站位，尽可能保留视角 | 普通墙边仰头九十度 | 种植或交互风险需要避让 |
| 单次转头、取消 | 单调到角度，释放后不恢复动作 | 来回摆头、取消后重新发起 | 正常物理减速 |

## 运行

```sh
python3 tests/integration/behavior_audit.py --sdk sdk/src --session /ABS/PERSISTENT_SESSION --out /ABS/NEW_EVIDENCE
# 可选 --only diag_ne,bridge8,eat_wall --repeat 3
```

检查器只连接已存在的隔离测试会话，不自动重启原生窗口；保持静音和鼠标自由。人工接管后停止推进，不自动重新获取控制。不要对课程公共服务器使用重置夹具。

截图不混入精密运动测量。高分辨率 PNG 写盘会造成假停顿，画面抽查单独进行。通过这些契约不等于所有主观细节都像真人；复杂组合、长期网络波动、任意地图及其他系统另行验证。

## 视点与姿态门槛（0.10.3）

`eye.y - position.y` 区分眼位降低与真实地形高低；包括动作结束后的 0.4 秒尾段。普通站立动作眼高变化上限 0.04 格，并要求服务器潜行起始次数为 0。这个门槛能检测旧版每次放置的 0.15 格蹲起。

- 连续桥段从首块确认到施工结束，眼高范围不超过 0.04 格；保留一次入场下蹲和离场站起。
- 造梯施工阶段无潜行放置，下降阶段单独记事件，仅允许一次必要蹲起。不能用“造梯需要潜行”掩盖每层放块抽动。
- 熔炉/工作台顶面放置和对熔炉进食允许必要下蹲，但要求成功、单次姿态周期且不意外打开界面。
- 所有动作结束后 yaw/pitch 在 0.4 秒内额外变化不超过 1 度。
- 转头额外路程使用最短首尾角度，不能把同向整圈旋转错误算作零绕路。

目录中的回调标志只描述所附固定版本 VoxeLibre。未知节点、旧目录、现场 groups 与目录不一致时仍使用保守潜行；同名同 groups 但回调被服务器自定义的情况不由目录证明。按服务器世界变化和背包扣减确认放置，不把目录当作执行成功。

场景重置后先核对两次血量及气息；潜水后的迟到伤害若发生于新技能开始之前，单独记录为夹具初始化失败并重置，技能开始后不重试掩盖失败。采集转场按实际采集批次与掉落物追踪事件约束，不能假定随机掉落时永远只需一个采集站位。普通砌墙还检查重复到达同一无效站位，避免理想格心射线掩盖真实眼位遮挡。
