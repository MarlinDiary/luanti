# 生存与长流程验收：SDK 0.11.2（2026-09-09）

后续 SDK 0.11.3 修复见 [撤离修复验证](retreat-validation.md)；以下保留本轮真实服失败与世界影响原始结论。

## 结论先行

**本地实际引擎的三个方向已执行并通过修正版回归；真实课程服没有全部通过。**
不能用本地 fixture 场景替代真实课程服结果，不能把被死亡/失去控制拦下的请求算作攻击执行。

| 方向 | 本地实际引擎 | 真实课程服 |
|---|---|---|
| 战斗、追击、避敌、低血撤退 | 修正版 wheel 对应场景通过；原生目标约束仍有效 | 多怪围堵中撤退失败并死亡；仅确认识别、抢占、撤离尝试、临界血量决策和死亡停止，未完成成功实战验收 |
| 进食、恢复呼吸、离开伤害区 | 真实库存食物减少、呼吸恢复、脱离火源通过 | 本轮未完成实际进食、水险/接触伤害场景验收 |
| 采集—中断—生存反应—重新规划—续任务 | 两条长流程共 8 个动作检查通过，另有学生示例实际执行通过 | 合成木剑后普通任务被遇敌反应中断，但后续死亡，未完成课程服长流程 |

## 真实服影响与失败现场

通过 Chrome 扩展启动已有世界，正常客户端身份认证，未重置世界、部署 fixture、补发物品或修改课程配置/时间天气。账号 `cni586`，服务器 `play.minecraft.elliottwen.info:30000`。测试静音、后台运行。

这轮不是无损只读测试：使用原有材料制作了一把木剑（木板 2、木棍 1），临时工作台放在 `[-7,17,-3]`；收回工作台的采集任务被遇敌中断。首次死亡位置约 `[-17.86,13.5,-3.91]`，原携带木剑、木镐、木板、木棍、骨头掉落。尝试正常复活/拾取没有取回原装备。末次背包为空，角色在死亡状态；世界已保存，服务器已停止。工作台、掉落物及怪物爆炸对世界的影响没有通过管理手段恢复；掉落物是否仍可取回未确认。

服务端聊天记录了四次死亡：21:30:22 僵尸；21:39:31 骷髅；21:41:26 Stalker 爆炸；21:44:30 僵尸。后续恢复尝试并非成功复测，均保留为失败证据。正常复活后的一个过渡曾因仍有菜单被 `close_menu_before_acquire` 正确拦截；重连后继续，但没有据此放宽控制权限制。

测试编排也有不足：人工工具往返与其他验证工作期间，角色仍留在有威胁的真实世界，快速反应层不是完整生存规划者。后续高风险验收应使用预先编写、连续运行的有界计划和每阶段退出条件，而不是将等待工具操作的时间当作合格的无人值守生存能力。本轮结果不支持“真实服无人值守已可靠”的结论。

证据根目录 `build/evidence/survival-live-v0.18/`；初次真实服为根目录中的 `results.json`、`samples.jsonl`、`events.jsonl`，后续为 `remote-retry2/`、`remote-retry3/`。`remote-retry/` 因测试注入库路径错误在连接前退出，单独保留，不计游戏测试。

## 已修复、有复现记录的问题

1. **部分撤离进展被当作无路**：整段增加 3 格距离不可达时，原逻辑立即失败；现在在已知可达点中选择真实改善的短段路线，避免直接穿入另一个已观察近战威胁的 3 格范围。
2. **紧急失败后固定等待 3 秒**：撤离、呼吸恢复、脱离接触危险失败后的重评间隔改为 150 ms（另加观察/规划耗时），普通失败仍有较长退避。失败事件仍要求上层重新计划。
3. **安全距离边缘反复规划**：路径跟随容差会使实际位置停在阈值内侧；目标增加 0.5 格余量。不是扩大攻击距离或瞬移。
4. **移动目标准星竞争**：观察时瞄准、提交时目标已移动，导致整个攻击过早退出；现在只对明确被拒绝的 `entity_not_in_crosshair` 重新观察瞄准，不计攻击次数；控制权丢失、实例过期继续终止。
5. **生物观察半径大于地图观察半径**：追击远处已复制目标时，不能要求一次获得完整接近路线；现在逐段接近，最后一步仍验证视线、距离和原生射线。

变更位于 `combat.py` 的 `chase`、`attack`、`flee` 以及 `supervisor.py` 的紧急失败退避。原生客户端保持 0.8.0，不修改协议或服务器。

## 本地回归与证据边界

- 305 项单元测试通过；新增 8 项覆盖部分撤离、未知地形、紧急退避、准星竞争、身份/控制权限制和追击观察范围。
- `flee-red.json`、`aim-red.json`、`chase-red.json` 保存修改前失败；对应 green 和 `final-unit.json` 保存修改后结果。
- `wheel-survival/`：安装 0.11.2 wheel 后 17 项实际引擎场景全部通过。
- `local-long-memory/`：8 项动作检查涵盖两条长流程：遇敌中断/撤退、主动规划处理追兵、按剩余数量采集并合成；饥饿中断/消耗苹果、继续采集并合成。地图记忆只来自此前观察，fixture 切换时清空。
- `example-result.json`：公开学生示例真实执行，采集中因饥饿中断、食物实际减少、重新规划后共获得 2 个木头，结果 `complete`。
- `local-long/` 暴露远距离追击缺陷；`local-long-corrected/` 还出现无地图记忆、未观察到剩余资源时的有界搜索超时。前者已修复；后者没有被伪装成全图搜索能力，最终测试使用可观察资源布局和显式局部地图记忆。早期失败保留，最终输入变化明确记录。
- `motion-metrics.json` 是观察采样诊断，包含 fixture 准备阶段且非等间隔视频帧，不作为逐帧抖动证明。最终单骷髅样本撤离 2.78 秒、11 次重规划；中间版本一次样本 12.34 秒、191 次重规划。生物运动有随机性，这不是严格性能基准，更不证明任意地形/多敌场景自然流畅。
- Windows 实机验收、本轮真实服进食/水险/火险、成功多敌逃生和完整课程服长流程仍未完成。
