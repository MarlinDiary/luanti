# SDK 0.12.0 / 客户端 0.9.0 收尾

## 新增能力

- `attack_ranged(target, shots=..., charge=...)`：只使用已有弓箭，以弹药减少确认射击；
- `block_with_shield(target, duration=...)`：用可见盾牌 HUD 确认举盾和释放；
- `avoid_projectile(target)`：有盾举盾，否则根据可见速度做一次平滑侧移；
- `survive_blast(target)`：对可见爆炸类生物举盾或连续撤离；
- `extinguish_fire()`：以可见火焰 HUD 判断持续燃烧，前往已观察水域并确认熄灭；
- `Agent` / `CommandPlanner`：模型无关、强类型、逐技能重规划的参考循环。

原生观察 schema 7 新增 `hud_images`，只导出玩家本来可见的 HUD 纹理名，不导出服务器脚本内部状态。实体分类识别 VoxeLibre 的实际箭实体和 stalker 爆炸威胁。

## 生存优先级和流畅性

优先级为：缺氧、接触危险、持续燃烧、来袭投射物、爆炸距离、撤离/自卫、进食。只有一个动作所有者和一个输入租约；高优先级反应让当前技能先清理，再接管。

连续撤离本身已经是规避运动，因此不会为每一支短命箭取消并重启撤离；正在进食或静止攻击时仍可被来袭箭抢占。这样避免“走走停停”和目标已消失后的无效侧移，同时保留真正紧急的缺氧、火源和持续燃烧抢占。

## 课程边界

SDK 完成单个技能的机械细节，但不完成学生应写的策略：

- 不自动决定去找钻石；
- 不选择下挖深度、矿道布局或工具升级顺序；
- 不把 `dig_down`、`go_to_surface`、`bridge_to` 串成固定答案；
- blocked/cancelled 后不自动重播原任务。

参考 Agent 展示如何把观察、一个技能调用和结果串起来；模型/学生仍负责下一步。

## 已验证与结论边界

本地真实引擎场景覆盖持续燃烧、盾牌、弓箭、真实投射物、实际 stalker 和参考 Agent 循环；原有地形、寻路、战斗、复合采集/合成与水边采集套件继续回归。UDP 故障审计使用真实本地专服、真实客户端和中间代理，不以 mock 代替链路。

真实课程服审计只做普通玩家可做的观察、装备和撤离，不安装 mod、不改地图、不读取隐藏数据。Windows 仍以实际 runner/实机结果为最终平台结论。

本轮最终记录包括：441 项 SDK 单元测试、51 个原生模块中的 350 项测试、15 个地形场景、6 个新增生存场景，以及水域采集 5/5。浅水 source 场景额外重复 3 次，其中一次实际出现只确认 2 个掉落，SDK 保留进度并另采 1 个后完成，不把挖掉方块误算为库存。

真实 UDP 审计通过四阶段：90 ms 单向延迟并每 23 包丢 1 包、全断网后输入租约清理并恢复、服务端终止后 bridge 清理、服务端重启后新客户端重连。真实课程服长链完成观察、装备现有最佳装备、撤离判断、再次观察；角色仍存活，自有客户端退出 0，未重置世界或自动复活。50 ms 前台采样期间 Luanti 未成为操作系统前台，结束后门户确认世界已保存、服务器由所有者停止。
