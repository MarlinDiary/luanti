## 本轮脚本修复与验证

1. `execute_plan` 的 JSON 使用 `item`，但 `Game.collect` 参数叫 `resource`，真实服复现 `TypeError`。现只在调用采集时转换参数名。相同输入的单测从失败变为通过，本地真实引擎也实际采到 2 个木头。
2. 仅在启动系统 Python 前设置 `DYLD_INSERT_LIBRARIES` 会被 macOS 清理。之前多次连接出现 `focused=True`，也没有生成预期焦点审计日志，**先前“全程后台”的预期没有全部达到**。现在用 `COURSE_TEST_DYLD_LIBRARIES` 传递已存在的两个库路径，在 Python 内构造原生子进程环境，并为本次输出目录生成焦点/光标日志；macOS 缺少这两项时在原生启动前报错。
3. 原生连接建立后 SDK 请求超时从 1 秒恢复到 4 秒，避免新 profile 首次加载时把正常慢帧误当作断线。

修正后的 `watcher-corrected/`：连续观察成功，`focused=False`、`audio_enabled=False`，焦点日志确认阻止窗口激活，光标日志没有捕获/重定位记录。此修正只在旁观连接复测，不追溯改写之前主角色的焦点记录。

全部单元测试 **325 项通过**；恢复修改前验收脚本的副本重新通过 **322 项旧测试**。SDK wheel 与原生应用没有重新发布。
