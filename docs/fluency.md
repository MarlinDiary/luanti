# 连续动作与视角（SDK 0.10 / 课程客户端 0.7）

这轮调整的是动作怎么完成，不是替学生选择长期目标。仍需学生决定找什么、往哪里挖、何时返程、走哪条发展路线。

## 动作改动

- **直线搭桥**：面向身后的支撑面，蹲着向目标倒走；视线方向与移动方向分离。固定俯角，只在实际准星命中正确支撑面时放置。每块都要看到世界更新和库存恰好减少一块，才继续；不再每格“走正—转身—放块—转回来”。开始和结束仍有必要的转身。
- **施工站位**：按多个可见放置面的覆盖范围选择站位，优先从同一个位置完成一组方块。已有姿态可放置时不强行移到格子中心；图纸使用固定扫向，避免最近邻排序不断折返。
- **接近交互物**：用普通横移/倒走保持视线朝向目标，不必先看移动方向、到达后再转回目标。已经对准时不重复瞄准。
- **返程**：合并已观察且仍可通行的连续矿道段，不再每个格子调用一次“走到并停下”。途中变化仍检查、重规划；到达入口才正常减速停止。
- **上岸**：游泳输入改在每个物理子步重新计算，而非一帧内多次物理推进沿用同一跳跃输入。接岸落地后不把旧游泳脉冲变成新一轮地面跳跃。原生重力、浮力、碰撞和速度不改。

工具切换、挖掉挡路方块、跨高度施工、门交互和服务端确认仍可能需要停顿。不是用删除确认或无限按住输入换取表面连续。

## 学生低层接口

现有高层调用不变，例如 `game.bridge_to(position)`、`game.build(blueprint)`、`game.return_to_entrance()`。

```python
# 在已有 game.control() 内；这是控制接口示例，不是无条件放块的搭桥脚本。
with game.motion() as motion:
    motion.steer(heading=90, move_heading=-90, pitch=80, speed=.4, sneak=True)
```

`heading` 是视线的世界角度，`move_heading` 是移动的世界角度；省略后者时移动目标方向与视线目标方向一致，保留原有调用形式。`place=True` 可在 steering 更新中按普通右键；下一次调用省略或设为 False 即释放。高层搭桥负责准星、预算、材料及确认，学生不需要复制内部循环。租约默认 0.4 秒，退出 scope 或显式 stop 都释放输入。

新的能力标记为 `independent_heading`、`steer_place`、`physics_swim`；观察增加实际准星相邻面 `pointed_above`。SDK 0.10 连接旧原生客户端时保留原有算法，但旧客户端不获得新原生能力或子步上岸修复。要使用本页全部改进，应同时更新客户端 0.7 和 SDK 0.10；仅更新 Python 不够。

## 边界与验收

连续倒走只用于已观察、同高度、轴向直线、有正常支撑的跨度。拐弯、上台阶、混合挖建仍使用原有有界规划/施工，而不是把任意复杂路线假装成直线。材料、操作预算、未知地形、头顶障碍、伤害和取消都会中止；已有世界变化保留在结果中。

同输入前后对照包含八格桥、八级矿道返程、六格隧道、五块木头采集和六块图纸施工。记录耗时、视角累计路程、停止指令、角色轨迹与真实库存。停止指令数不是肉眼卡顿次数；网络端瞬时 yaw 也不等于逐帧渲染相机速度。

完整本轮证据位于 `build/evidence/fluency-v0.10/VERIFICATION.md` 和 `verification.json`，包括失败的开发尝试、最终回归、原样输出、源码/应用哈希与回滚验证。有限夹具验收不代表任意地图、模组或网络条件的绝对保证。Windows 实机和课程服务器仍需分别验收。


## 观感复查（SDK 0.10.1）

功能完成不是自然度通过。本轮分别检查真实画面、客户端姿态轨迹、服务端运动和材料数量；停止指令数不是肉眼卡顿次数，也没有一种全局角度阈值可以代替具体动作判断。

- 水面斜游通过已知、无害、全身体积可通行的水域走廊直达，不追逐格子折线。未知空间、实体障碍、熔岩和未开启的主动下潜仍阻止捷径；意外下沉后的上浮恢复不等于打开主动下潜。
- 向上跳台阶时不再回头追已越过、暂时位于身下的踏步；在终点上方短暂腾空时不因为微小水平误差转身。
- 下挖、造梯采用预计落脚位置的下一工作面安排视角，减少抬平再低头及近点俯仰过冲。实际工具、挖掘、碰撞、材料和确认保留。
- 进食时如果当前视线没有指向方块，保留原有视角，不再强制仰望天空；有方块可能拦截右键时仍保留已有的对空使用回退。
- 已选站位还有可达工作时先完成工作，不在每放一块之后重新优化站位。
- `game.hold(..., seconds)` 原生租约不超过剩余时长；显式 `game.motion()` 连续作用域保留原有短租约语义。Python 卡顿不再把一次 120 ms 短按延伸成 400 ms 长按。

场景重置属于夹具准备，不是角色能力。演示等候会显式维持游泳高度；技能结束仍释放输入，不在后台自动悬浮。截图本身有开销，截图时点与采样间隔保留在记录里；这不是无采样干扰的帧率基准。

复查证据位于 `build/evidence/naturalness-v0.11/`。固定本地场景的结果不代表所有地图、模组、网络状况都有相同观感。

## 0.10.2：简单场景的预期与实际

- 平地直线推进不再追逐格点；远处未知目标只沿完整已观测、有支撑且净空的短线推进，遇障碍回到图搜索。
- 旋转碰撞盒仅消除浮点零点误差，保留真实间隙和全角色体积检查。
- 中途落差落地时不追厘米级水平误差；沟边助跑后退时看向落点。
- 冰面依据原生加速度和 `slippery` 属性提前减速，低速后才确认抵达。
- 普通墙边进食保留视角；顶部、相邻耕地或未知支撑仍采用避让瞄准，避免误种植。
- 地面短线推进与水域专用控制分开，避免互相覆盖。

行为契约见 `docs/behavior-contracts.md`，运行器为 `tests/integration/behavior_audit.py`。每次记录真实姿态、指令、规划路径、事件和采样空隙。复杂组合场景留待下一阶段，单纯技能成功不作为动作自然的证明。

## 0.10.3：放置引起的相机蹲起

复查发现原来的位置/yaw/pitch 检查漏掉了眼高变化。普通放置无条件发 `sneak + place`，真实脚位不动而眼高从 1.60 降为 1.45 格，造成视觉抽动。现在普通放置与进食不再潜行；需要绕过节点交互、桥边防坠落和沿梯下降的动作仍保留对应姿态。造梯施工与下降分阶段判定，新增眼高、潜行按键和结束后视角稳定性检查，详见 [动作契约](behavior-contracts.md)。

这次仍是 SDK 变更，未修改原生动画/视点参数，未关闭正常游戏效果，原生窗口可继续复用。
