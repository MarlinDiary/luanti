# Luanti Course

## 课程版收尾（SDK 0.12.0 / 客户端 0.9.0）

本轮补齐了持续燃烧、盾牌、弓箭、来袭投射物和爆炸威胁；生存监督仍只做快速保命反应，任务目标与失败后的重新规划仍由学生负责。`Agent`/`CommandPlanner` 提供一个模型厂商无关的参考循环：每轮只接收有限观察、选择一个白名单技能、读取真实 `SkillResult` 后再规划，不内置“获得钻石”等课程答案。见 [课程版收尾](docs/course-completion.md) 和 [参考 Agent](docs/reference-agent.md)。

macOS 应用已在本机做后台、静音、无鼠标捕获和真实引擎长流程验证；同一提交的 GitHub CI 已实际完成 macOS arm64、Windows x64 和 Python wheel 构建并上传制品。Windows 实机启动、控制与焦点冒烟仍单列待验，不用 runner 编译代替。见 [跨平台交付](docs/cross-platform.md)。

## 水边采集修复（0.11.8）

采集站位避开待挖方块支撑；支持明确允许游泳时的浅水涉水；水面路径先恢复角色实际高度再出发。详见 [水边采集验证](docs/water-harvest.md)。不改变地图、课程目标或学生负责的采矿策略。

## 生存与任务完成交接（0.11.7，历史修正）

已观察到的生存反应在进入作用域时立即挂起普通任务；技能途中发现缺氧/接触危险，也及时交给唯一的反应执行线程。采集示例在数量达标后仍等待当前反应、检查结果和最新库存，再报告完成。掉落物消失后停止追逐旧位置，仍只以库存增量确认拾取。没有自动重播任务、增加隐藏输入线程或改变学生策略。见 [当前收尾与验证](docs/sdk-closure.md)。

## 连续路线与撤离修正（0.11.6）

`navigate_route()` 连续通过中间路点、只在终点停稳；已知路段尽头缺乏安全缓冲时仍减速。撤离增加有界的侧向观察，追兵位置每次观察都更新路径约束，不再按固定移动距离反复释放输入。独立的 `navigate_to()` 仍是“走到并停下”。测试继续复用静音后台客户端。见 [本轮行为修复与验证](docs/behavior-repair.md)。


可见的 Luanti 课程客户端与零运行时依赖的 Python SDK。学生可以用普通 Python 循环或自己的 Agent 框架，控制正在观看的同一个角色。

```python
from luanti_course import Game

with Game.connect() as game:      # 先在课程客户端中进入世界
    with game.control():
        result = game.craft("wooden_pickaxe")  # 使用已有材料，可自动制作中间件
        print(result.to_dict())
```

## 已实现的层次

- 原生客户端：画面、正常游戏交互、结构化观察、本地控制接口。
- 基础 SDK：移动、视角、挖掘、使用/放置、背包与合成格操作。
- 高层技能：连续路径跟随与平滑视角、A* 寻路、有限范围探索、成组采集、掉落物追踪、批量合成、有界恢复、按名称装备/放置、无损背包整理；使用实际碰撞盒支持半砖/楼梯/薄层和梯子，支持开门、梯子、地形净空偏移；水面/潜水、跨沟、挖路与消耗材料搭桥/垫台阶可选。
- 学生动作：平滑 `look()`、显式 `game.motion()` 连续短循环；异常退出和停滞租约都会停止。
- 控制互斥：默认观看；Agent 运行不抓鼠标；F8 显式人工操作，Esc 停止并释放。

请先看 [控制模式](docs/control-modes.md)、[技能 API 与边界](docs/skills.md)、[地形覆盖与验收边界](docs/terrain-coverage.md) 和 [示例](examples/wooden_pickaxe.py)。

## 生存与快速反应（0.11）

客户端 0.8 新增生物/饥饿观察与目标绑定攻击；SDK 0.11 提供追击、自卫、动态撤离、自动挑选已有食物/装备、浮出水面和离开接触伤害区域。
`with game.survival():` 显式启用 Mindcraft 式快速反应，默认避敌；普通任务被打断后返回原因，由学生重新计划，不重放任务、不修改课程地图/规则。见 [生存 API 与边界](docs/survival.md)、[验证记录](docs/survival-validation.md) 和 [普通 Python 示例](examples/survival_loop.py)。

## 参考逻辑对齐（0.11.4）

逐项对照固定版本 Mindcraft 及其寻路、战斗、进食插件：自卫持续重选附近目标，紧急反应可打断正在执行的低优先级反应，撤离默认连续复查 1 秒后才交回任务层。单目标攻击、武器冷却、控制互斥和学生显式重新规划保留；不自动完成课程目标。来源、差异、测试与未覆盖项见 [行为对照与验证](docs/mindcraft-alignment.md)。

## 生存收尾（0.11.5）

正常的高优先级抢占不再被配套采集示例误判为反应失败，交接期间 `wait_idle()` 继续等待；成功的自动/优选进食会恢复原持物，紧急中断或人工接管不追加恢复动作。学生仍负责观察后重新规划。见 [收尾验证与真实服边界](docs/sdk-finishing.md)。

## 学生技能边界（当前 SDK 0.12.0）

保留完整导航和有预算的地形处理；默认合成只用已有材料，默认不自动制作/升级缺失工具。新增按深度下挖、定向隧道、返回入口、搭桥到达、进食，以及挖掘检查点续做。学生仍决定目标、找矿策略、工具升级和任务顺序。

先看 [功能清单与边界](docs/student-skills.md)，再看 [工作流](docs/skill-workflows.md)。当前 SDK 0.12.0 / 原生客户端 0.9.0 保留这些策略边界，并提供下述生存能力。

## 连续动作（0.10）

直线搭桥保持朝后连续倒走；施工共享站位、固定扫向；交互移动保持目标视线；矿道返程连续跟随；上岸在物理子步修正旧跳跃输入。见 [实现与验收边界](docs/fluency.md)。更新本轮原生客户端后，后续 Python 脚本迭代仍复用同一游戏进程。

## 隧道侧壁交互修正（0.10.4）

狭窄隧道中，矿石中心可能被顶上的石头遮住，但露出的侧面仍可交互。SDK 保留原来的中心瞄准优先级，必要时在已观察到的完整方块表面寻找可见落点，并保持已经确认的瞄准方向；不延长触及距离、不自动挖遮挡物、不改变学生的采矿策略。复杂场景与持续运行检查见 [验证说明](docs/complex-validation.md)。

## 放置视点修正（0.10.3）

普通砌块、造梯背板/梯子、普通进食不再无条件短按潜行。固定版本游戏目录补充右键/表单回调信息；交互方块和未知定义保留潜行，搭桥防坠落与梯子下降的必要姿态不变。验收同时跟踪真实眼位、脚位、按键和动作阶段，不再只看位置与 yaw/pitch。

## 观感复查（0.10.2）

水中直线走廊不再追逐锯齿格点；上楼梯越过踏步后不再回头追旧点；下挖和造梯在移动中预看下一处工作面；已选施工站位先用完眼前可达工作。短按输入的原生租约受剩余按压时长约束，避免 Python 卡顿时重复放块。高层能力与学生策略边界不变；本次只更新 SDK，复用原生客户端 0.7。参见 [观感复查及限制](docs/fluency.md)。

## 决策辅助（0.9）

新增只读配方/材料计划、命名地点的保存与返回、箱子内容检查，以及显式复制升级旧版检查点。只提供做决策需要的信息与完整动作，不自动替学生决定发展路线。详见 [决策辅助 API](docs/decision-support.md) 和 [只读示例](examples/inspect_and_plan.py)。

## 安装与运行

当前开发产物在 `dist/`：macOS Apple Silicon 应用、Windows x64 ZIP 与 Python wheel。打开课程客户端并进入世界，再安装 wheel：

```sh
python -m pip install --upgrade dist/luanti_course-0.12.0-py3-none-any.whl
python -m luanti_course doctor
```

开发环境也可使用 `python -m pip install -e .`。学生不需要 C++、Node.js 或 Docker。Python 最低版本为 3.9。
